# Agent Note: 在 xAI catalog 路由上提供 Grok 4.6

Status: implemented

[English](2026-08-14-xai-grok-4.6-catalog.md) | 中文

## 问题

xAI 在 2026-08-12 发布了 `grok-4.6`。`dsh login xai` / TUI `/login` 之后，`/model` 仍只列出已安装 `@earendil-works/pi-ai` 的 xAI catalog；其最新已发布版本（0.84.1，2026-08-07）停在 `grok-4.5`。

## 决策

当已安装 catalog 没有这个 id 时，`catalogModels('xai')` 追加 `grok-4.6`：从 catalog 里的 `grok-4.5` Responses 描述克隆，并提供 `xhigh`。已安装的同名条目优先，因此下一版带上 4.6 的 pi-ai 不会留下两份描述。适配器不为这一个模型改用 `@oh-my-pi/pi-ai` / `pi-catalog`。

## 考虑过的替代方案

**把 `@earendil-works/pi-ai` 升到 0.84.1。** 不能当修复：那份 tarball 仍然没有 `grok-4.6`。以后带上该 id 的升级会自动退役这份补充。

**依赖 `@oh-my-pi/pi-catalog`。** 否决：[TUI catalog 笔记](2026-08-14-tui-omp-engine-and-catalog.md) 已经拒绝在 `getBuiltinModels()` 旁边再放第二份目录。

**让用户在 `settings.yaml` 的 `models` 里列出 `grok-4.6`。** 否决：`models` 列表会替换整份 xAI catalog，加一个 id 就会丢掉 4.5 / 4.3 / Build，除非把其余 id 全部重写一遍。

## 后果

活的 xAI 登录会列出带 `low` / `medium` / `high` / `xhigh` 的 `grok-4.6`。请求走与 catalog `grok-4.5` 相同的 Responses 协议。

## 测试

`packages/llm/llm-pi-ai/tests/catalog.spec.ts` 钉住 `catalogModels('xai')` 在 Responses 上暴露带 `xhigh` 的 `grok-4.6`，以及 `supplementCatalog` 对已存在的 id 原样返回。
