# Agent Note: Offer Grok 4.6 on the xAI catalog route

Status: implemented

English | [中文](2026-08-14-xai-grok-4.6-catalog.zh.md)

## Problem

xAI shipped `grok-4.6` on 2026-08-12. After `dsh login xai` / TUI `/login`, `/model` still listed only the installed `@earendil-works/pi-ai` xAI catalog, whose latest published release (0.84.1, 2026-08-07) stops at `grok-4.5`.

## Decision

`catalogModels('xai')` appends `grok-4.6` when the installed catalog omits that id, cloned from the catalog `grok-4.5` Responses descriptor with `xhigh` offered. An installed entry of the same id wins, so the next pi-ai bump that ships 4.6 does not leave two descriptors. The adapter does not switch to `@oh-my-pi/pi-ai` / `pi-catalog` for this one model.

## Alternatives considered

**Bump `@earendil-works/pi-ai` to 0.84.1.** Rejected as the fix: that tarball still has no `grok-4.6`. A later bump that includes the id retires this supplement automatically.

**Depend on `@oh-my-pi/pi-catalog`.** Rejected: [the TUI catalog note](2026-08-14-tui-omp-engine-and-catalog.md) already refused a second catalog beside `getBuiltinModels()`.

**Ask the user to list `grok-4.6` in `settings.yaml` `models`.** Rejected: a `models` list replaces the whole xAI catalog, so adding one id would drop 4.5 / 4.3 / Build unless every other id is restated.

## Consequences

A live xAI login lists `grok-4.6` with `low` / `medium` / `high` / `xhigh`. Requests use the same Responses wire as catalog `grok-4.5`.

## Testing

`packages/llm/llm-pi-ai/tests/catalog.spec.ts` pins `catalogModels('xai')` to expose `grok-4.6` on Responses with `xhigh`, and `supplementCatalog` to leave an already-present id untouched.
