# `@deepseek-ai/dsh-tui`

English | [中文](README.zh.md)

The dsh interactive terminal bundle. The `dsh` launcher boots this profile when `--profile` is omitted. [`cordis.patch.yml`](cordis.patch.yml) rides directly over [`dsh-base`](../base/README.md): it supplies the coding persona and tool mode, disables HMR, mounts Code Mode's worker as a core execution capability, and inserts this package's `tui-runtime` plugin (config `{resume, theme}`, resolved from the injected `tuiStartup` provider). It mounts no Host, HTTP server, Web runtime, or browser plugin. The patch inserts [`dsh-agent-presets`](../../preset/agent-presets/README.md) (`default: standard`) and disables the host-plane tool rows so each session joins a standing preset; `apps/cli`'s `composeProfile` patches in the shipped root.

After the Loader settles, the runtime reads the shared [`ctx.agentDefaultModel`](../../core/agent-default-model/README.md), creates or resumes one persisted Agent through `ctx.agents`, and owns the TTY through [`@oh-my-pi/pi-tui`](https://www.npmjs.com/package/@oh-my-pi/pi-tui). The Node `dsh` launcher re-execs this profile under bun >= 1.3.14; missing bun is a usage error before the TTY check. The session layout follows Pi's interactive TUI with OMP chrome: a colored product header with key hints, a transcript of a user-message bubble, dim Thinking blocks for `reasoning-delta`, Markdown assistant blocks, and [`presentCall` / `presentResult`](../../core/tools/README.md) tool cards, and one live card per `subagent/start` — labelled from the child log's `subagent/descriptor`, folding the child session's own tool activity into a rolling feed, and settling with the run's stop reason on `subagent/end` — a muted rounded-border editor, and a cwd/model footer that also counts running subagents and, once the first turn reports token usage, inserts a dim durable stats row above the model row showing cache-hit percent, billed input and output tokens, decode throughput in tok/s, turn count, context occupancy (`ctx N% used/window`), and heuristic `~sys` / `~tools` / `~msg` composition from `contextBreakdown`, all read from the `token-meter` and `session-stats` session projections so the figures survive paging and compaction. A spinning loader ticks at the transcript tail while the Agent waits for the model (`Thinking`) or a tool is running (the call's `presentCall` title); the first reasoning or answer token replaces it. A settled subagent run rings BEL; live runs set the window title to `dsh · N subagent(s) running`. A `card: 'diff'` call (write, edit, `str_replace_editor`) paints `+`/`-` hunks collapsed to eight rows; Ctrl+O expands the last tool card and Alt+O opens a fullscreen overlay the mouse wheel can scroll. The editor and footer sit on the last rows of the TTY until the transcript fills the viewport. `/model` (also Ctrl+P / Alt+P) lists registered `ctx.llm` routes — DeepSeek official, settings-configured pi-ai profiles, installed-catalog providers whose ambient API keys are already set, and Ollama Cloud when `OLLAMA_API_KEY` is set — and, when a selected model exposes selectable reasoning efforts, opens a second picker for the effort level before writing the live selection and persisting it through `agentDefaultModel.saveSelection`. The footer appends the current effort as `· <effort>`. An `llm/adapters-updated` commit rebuilds an open `/model` picker and notices newly registered provider ids, so a `dsh login` in another process appears without restarting the TUI. `/theme` lists the built-in palettes Dark, Tokyo Night, Catppuccin, and Light plus `$DSH_HOME/themes/<id>.json` files (oh-my-pi JSON with `colors` / `vars` is accepted for this token set), applies the live palette, and persists the id in the `tui-theme` settings section. `/settings` opens a settings hub: Appearance reuses `/theme`; Models lists configurable `ctx.llm` providers and writes an API key through `ctx.credentials` plus a `baseURL` through `ctx.settings.mutate` (Login still goes to `/login`); Permission switches the active [`ctx.permissionPresets`](../../interaction/permission-presets/README.md) bundle (sandbox mode + approval policy) for the current session, with the derived `custom` row shown but not settable; Inventory lists the loader's mounted plugin entries (`ctx.loader.entries()`) read-only; Settings file notices `ctx.settings.documentPath` when the provider stores one local file. Typed lines become ordinary user messages; idle Enter paints the user bubble immediately and starts a follow-up turn; while a turn is running, Enter steers the text into that turn at the next step, shown as a dim `appending` line until claimed. A status-chip row appears above the model row while plan mode is on (or pending), a goal is set, a standing todo list exists, or this session has visible background jobs — `/plan` and `/goal` stay the host commands; `/jobs` opens a picker over `ctx.jobs.list`. A missing projection or `ctx.jobs` omits that chip. Lines beginning with `/` stay in the [`dsh-commands`](../../interaction/commands/README.md) command plane (`/help`, `/model`, `/theme`, `/settings`, `/login`, `/logout`, `/auth`, `/sessions`, `/jobs`, `/preset`, `/exit`, and `/quit` are registered here). `/preset` recomposes a blank session through [`ctx.agentPresets`](../../preset/agent-presets/README.md); a started conversation is locked. A `compaction/summary` paints a dim `compacted` row; a `feedback/record` paints the recorded text. Slash autocomplete also offers user-invocable [`ctx.skills`](../../skill/skill/README.md) names; a command name wins over a same-named skill. `/sessions` lists top-level sessions in every recorded cwd through [`ctx.sessionQuery`](../../session-query/session-query/README.md) and resumes the pick in-process; a running turn must finish first, and a failed resume leaves the current Agent. `/login` and `/logout` drive [`ctx.llmOAuth`](../../llm/llm-oauth/README.md) through overlays (provider picker, auth URL / device code, text prompts); `/auth` notices stored vs loginable providers. A successful `/login` is the same store write as `dsh login`, so `/model` refreshes on `llm/adapters-updated`. Ask-user prompts use [`dsh-user-questions`](../../interaction/user-questions/README.md) overlays. An `approval/request` for this session opens an Allow once / Reject overlay on [`ctx.approval`](../../interaction/user-approval/README.md); Escape cancels. Ctrl+C cancels a running Agent and exits when idle; Ctrl+D exits. Teardown stops pi-tui, drains input, flushes the Session, and requests exit through the launcher-provided `ctx.appExit` host hook ([`dsh-cmdline`](../../boot/cmdline/README.md)). A missing TTY is a usage error. The invocation is this app's command line: the ordinary `tui-startup` provider ([`src/startup.ts`](src/startup.ts)) injects `ctx.cmdlineArgs`, reads `--resume` / `--session`, prints the app's `--help`, and provides `tuiStartup`; the runtime injects that service and reads its resume id from lazy config.

## Model Experience

None, as the runtime submits typed lines as ordinary user messages; prompts and tools belong to the mounted agent preset, or to the host composition when no roster is mounted.

#### KV Cache effect

None; the runtime adds nothing to the request prefix.

## Known Limitations and Deferred Work

- **Theme files are not watched** — `/theme` re-reads `$DSH_HOME/themes` when the picker opens; editing a selected JSON does not live-reload. There is no OSC 11 auto dark/light switch and no bundled oh-my-pi default pack.
- **`/sessions` does not change the process cwd** — the picker lists top-level sessions in every recorded cwd (this process cwd first); switching resumes in-process the way `--resume <id>` does, and tools still run in the launch working directory.
- **Status chips and `/jobs` are visibility** — a missing `plan` / `goal` / `todos` projection or `ctx.jobs` omits that chip; `/jobs` notices status and detail and does not cancel work.
- **Models settings write keys and base URL, not full profiles** — `/settings` → Models stores an API key through `ctx.credentials` and a `baseURL` through `ctx.settings.mutate`; it does not edit model lists, protocol, or `settings.yaml` by hand. Settings file notices the local path and does not open an editor. `/login` remains the subscription OAuth write.
- **No locale switcher** — Web's `dsh-client-locale` is a browser plugin; the TUI strings stay English.
- **No Trajectory table** — the transcript is the conversation; there is no second structured log view.
- **Editor is text-only** — image content blocks already paint in the transcript as `[image]`; the editor does not attach files.
- **No Like/Dislike chrome** — `/feedback` from `dsh-command-feedback` still records a session-level note when that command is mounted.
- **Interactive `dsh` requires bun >= 1.3.14** — `dsh web` and `dsh --profile headless` stay on Node; dump-config and launcher `--help` do too.
- **Context occupancy appears only after the first request** — `contextWindow` is read from the first `request/context` record, not preheated from `resolveModelInfo`, so the `ctx` group stays empty before the first billed turn reports a sample.
- **Subagent cards are live-only** — the `subagent/start` / `subagent/end` lifecycle is transient, so `--resume` replays the delegation's durable tool call and result but not the run's activity feed.
- **`ctx.appExit` is launcher-owned** — booting the tui profile outside the `dsh` launcher fails loud at activation until the host provides the exit request.
